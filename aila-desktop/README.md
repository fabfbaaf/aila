# 艾拉 · 程序员的 AI 桌面伙伴

常驻桌面的 3D 数字人助手。当前进度：**第 1–5 周完成**——透明桌面窗口、角色渲染、待机动作、点击互动、拖动；和她打字或说话聊天，她出声回答，口型、表情和动作跟着声音走，说话时可以随时插话打断；她会记住你说过的事，能翻你放进来的资料；聊天记录和记忆登录后在几台电脑之间同步；所有设置集中在一个设置窗口里。

## 运行

对话和语音要先启动本地 AI 服务（在旁边的 `aila-ai` 目录，见它的 README，语音模型要先下载）：

```powershell
cd ..\aila-ai
.venv\Scripts\python -m app   # 127.0.0.1:8765；没填密钥时用假模型
```

然后启动桌面端：

```bash
npm install
npm run dev        # 启动桌面版（Electron）
npm run dev:web    # 只在浏览器里调试角色、行为、对话和语音，地址 http://localhost:5180
npm run setup:gestures  # 手势要用：把 MediaPipe 的识别程序和手部模型放到 public/mediapipe（一次就行，约 35MB，不进 git）
npm test           # 单元测试（切句、口型、回声判断、语音会话、同步引擎、记忆）
npm run typecheck  # 类型检查
npm run build      # 打包到 out/
```

| 右键「编程任务…」 | 打开工作窗口：选一个项目文件夹和权限模式，给她一个任务（「给购物车加打折函数，写好测试并跑通」）。她读代码、改文件、跑命令，每一步一张卡片：改文件给彩色 diff，跑命令给输出，待办清单实时打勾；改文件、跑命令前卡片里直接问你（`1` 可以 / `2` 以后都可以 / `Esc` 不要）；`Esc` 打断。右边是待办、改过的文件、缓存命中率。终端里 `aila` 开的会话也在左边列表里 |

| 右键「代码星图…」 | 打开魔法工作台：登记的项目里每个文件是一颗星球（大小看行数、颜色看子项目、没提交的改动亮一点），文件之间的调用是光线，光点沿调用方向流动；拖动旋转、滚轮缩放、搜文件；点星球飞过去，右边的全息面板列出函数、预览代码，可以「问她」 |
| 星图里点「✋ 手势」 | 打开摄像头用手势操作（只在这台电脑上识别，不保存、不上传）：张开手掌移动旋转、双手拉开合拢缩放、剑指保持一下唤出全图（法阵特效）、捏住一颗星球往面前拉展开它的代码、握拳收起面板（没有面板就关掉星图）；她准备好代码修改时星图里也显示那份 diff，双手合十保持一秒确认 |
| 屏幕上看到报错时点「在星图里看」 | 星图里出错的文件变红、一跳一跳，往上的调用链变橙，镜头飞过去，面板里出错那一行标红；点「让她修」在工作窗口里开任务修它 |
| 屏幕上看到报错时点「交给她修」 | 报错落在登记的项目里时才有这个按钮：在那个项目里开一个修报错的任务，工作窗口打开、她开始做（改文件之前照样问你） |
| 对她说「编程任务：在 aila 里给购物车加个打折函数」 | 打字或者说话都行：她不在对话里写代码，而是在工作窗口里开任务去做（按名字找项目，有好几个就先问你是哪个） |
| 工作窗口里做任务时开着星图 | 她读的文件在星图上闪一圈青光，改过的变绿、显示名字，底下一行「她正在读 / 改 xx」；要你确认的改文件操作星图里也显示 diff，双手合十就是「可以」 |
| 工作窗口顶上点「轨迹」 | 每一轮一条时间线：她在想（浅色是等第一个字）、每个工具、等你确认各一行，带用时和每一步命中多少缓存，下面列出最慢的几步 |
| 工作窗口右边「上下文账本」 | 下一步发给模型的上下文由哪几块组成：整个窗口一条横条（黄线是压缩线）、用掉的部分各块的比例、开头固定命中缓存的有多少、最占地方的几个工具结果、每一步的缓存命中 |
| 新任务时勾「在新分支上做」 | 她在一个临时的 git 分支里改，你的代码一个字不动；右边「跑测试并合并」：测试全过、你这期间没改过同样的文件，才写回你的代码（不替你提交）；没找到测试命令时可以选「不跑测试直接合并」；「放弃分支」删得干干净净 |
| 「帮我修好它」 | 气泡里先给你看 diff（加的行绿、删的行红）和要跑的测试；点「好」后她在新分支上改、跑测试，全过才改到你的代码里，没过自动撤回（要接上真大模型） |
| 右键「留意屏幕上的报错」 | 她每 2 秒看一眼前台窗口（只看编辑器、IDE、终端），看到报错问你「要我帮你看看吗？」：「好」就把那几行报错交给大模型；「不用」；「一小时内别提醒」。开着时脚边显示「正在看屏幕」，默认关闭 |
| 「去 GitHub 上搜一下 three-vrm」 | 她开一个自己的 Edge 窗口去搜（你看得到）；点普通链接、搜索直接做，点其他按钮、提交表单前先问你；密码、验证码让你自己填（要接上真大模型） |
| 重启程序 | 她还记得刚才聊到哪了（最近 40 句带给大模型） |
| 右键她 | 菜单：和她说话、听我说、语音唤醒、出声说话、留意屏幕上的报错、技能包、编程任务、代码星图、资料库、她记得的事、设置、回到右下角、开发者工具、退出 |

### 设置窗口

普通的窗口（可以调大小），和桌面上透明的她分开。左边分区：

| 分区 | 能改什么 |
| --- | --- |
| 对话 | 大模型地址、模型、密钥（「测试连接」看对不对）；搜索服务和密钥。保存后立刻生效，写进 `aila-ai/.env` |
| 语音 | 语音唤醒、出声说话；声音引擎、语速（可以试听）；唤醒灵敏度、说完的判定停顿、识别语种 |
| 技能包 | 每个技能包的开关、有哪些工具、哪些要你确认；外部 MCP 服务的连接状态 |
| 资料库 | 添加、删除文档（只保存在这台电脑上） |
| 代码库 | 登记项目文件夹（主进程弹窗选，渲染层不能指定任意路径）、看索引进度和统计、重新扫描、不再登记 |
| 她记得的事 | 按类别列出，单条删除，或全部忘掉 |
| 账号与同步 | 登录、注册、退出；同步状态；登录着的电脑 |
| 形象 | 选 VRM 模型；让她回到右下角 |
| 运行状态 | 各个模型有没有准备好；配置、模型、数据文件在哪 |

密钥只能填不能看：保存后界面只显示「已设置」。在设置窗口里删记忆、加资料，桌面上的她会有反应。

语音唤醒默认关闭：打开后麦克风一直开着（声音只送到本机的 aila-ai，不出这台电脑），所以要你自己决定。

不登录也能用，聊天记录只存在这台电脑上。登录时，登录前的记录会并入账号；退出登录时清空本机的记录（云端的还在），换个账号登录也不会把上一个人的记录传过去。「出声说话」会跟着账号同步，「语音唤醒」因为要开麦克风，每台电脑单独决定。

她能做的表情：开心、难过、惊讶、放松；动作：点头、摇头、歪头、思考、鞠躬。由大模型在回复里用标签决定（`[happy]`、`[nod]`），解析在 `aila-ai` 里做。

角色以外的透明区域会让鼠标穿透到桌面，不影响正常使用电脑。

1. 用免费的 [VRoid Studio](https://vroid.com/studio) 捏一个角色，导出为 `.vrm`

没有模型时显示简易占位角色，所有互动照常可用。

## 几个设计点

- **鼠标穿透**：窗口默认穿透；渲染层读取鼠标下那个像素的透明度，落在角色身上才接收点击。比射线检测更便宜，也不受模型面数影响。
- **视线跟随整个屏幕**：窗口外的鼠标事件收不到，所以主进程每 33ms 轮询一次全局光标位置，推给渲染层。
- **行为和渲染分离**：`Behavior` 只算表情权重和姿态参数，角色实现只负责画出来。占位角色和 VRM 角色共用同一套行为。
- **平滑过渡**：所有表情和姿态都用和帧率无关的指数平滑，动作之间不会跳变。
- **动作和那句话同步**：网络一次可能来好几个字，也可能卡一下。回复先进队列，再按固定节奏（每秒 18 字，句号后停顿）放出来；标签排在文字中间，放到那里才触发。所以「[nod]今天也请多指教」一定是说到这句时才点头。
- **对话请求走主进程**：渲染层不用放开 CSP 和跨域，打包成 `file://` 后也一样能用；浏览器调试时走 Vite 代理，两条路共用同一套 SSE 解析。语音合成同样走主进程；语音的 WebSocket 不受跨域限制，由渲染层直接连，AI 服务检查 Origin。麦克风权限只给自己的页面。

### 同步

- **同步在主进程**：令牌、本地记录、和云端的连接都在主进程，渲染层只拿到对话记录和状态，碰不到令牌。
- **先存本地，再上传**：每句话说出口就带着本地生成的 UUID 存进 `history.json`，没有序号的就是还没传上去的。断网时攒着，连上后补传；UUID 保证重传不会重复。
- **推送只是提醒，数据靠拉**：WebSocket 只告诉「最新序号是 N」，比本地大就按 `since` 分页拉取。每次重连服务端先发 hello 带上最新序号，所以断线期间漏掉的推送不影响，重连后自动补齐。
- **连接自己会恢复**：断线后按 1、2、4……30 秒退避重连，带随机抖动（服务端重启后客户端不会同时涌上来）；每 25 秒心跳一次，10 秒没回应就主动断开重连（电脑睡眠醒来后不会挂着一条死连接）。
- **令牌**：访问令牌只在内存里；刷新令牌用 Electron 的 `safeStorage` 加密保存（Windows 上是 DPAPI，只有当前系统用户能解开）。刷新是「单飞」的：好几个请求同时发现令牌过期，也只刷新一次，因为服务端发现同一个刷新令牌被用两次会当成被盗，整个登录作废。
- **端到端测试**：`src/main/cloud/sync.e2e.test.ts` 连真服务器，两台「设备」互发消息、断线补齐（先启动 `aila-server`，设置 `AILA_SERVER_E2E=http://127.0.0.1:8790` 再跑）。开发时设置 `AILA_REMOTE_DEBUG=端口` 会打开远程调试，可以用脚本通过 Chrome 调试协议驱动真实窗口（打包后无效）。
- **一定有结局**：AI 服务没开、密钥错、余额不足、中途断开，都会归类成不同的错误，艾拉用不同的话回应，不会卡在「……」。
- **打断只记已说出口的部分**：被新消息打断时，历史里只存已经显示出来的那段，大模型不会以为用户听完了整句话（第 3 周语音打断也靠这个）。
- **搜索进度也排队**：AI 服务在调用工具前推一个 `status` 事件，它和文字排在同一个队列里，等「我查一下」说完才在气泡最后一行显示「（正在搜索「…」……）」，她同时摆出思考的样子；下一句开口时清掉。进度不算说出口的话，不进历史。

### 操作确认

- **问完再出按钮**：AI 服务推来 `confirm` 事件时，她先说一句「……要我{要做的事}吗？」（和平常说话一样打字或出声），说完才在气泡下方显示具体内容和「好 / 不要」。具体内容（比如完整网址）只显示不念，照 AI 服务给的原样显示，不经过大模型改写。
- **三种回答方式**：点按钮；在对话框里打字；语音会话中直接说。打字和说的话先过 `confirmIntent`：整句都是「好、可以、嗯、打开吧」这类词才算同意，短句里带「不、别、算了、取消」算不同意，其他话（问别的事、太长）不算回答，照常当新的一句话发出去——这会打断当前回复，操作随之作废。宁可认不出，也不能把「是什么网站？」认成同意。
- **按钮能点**：窗口平时只在角色身上接收鼠标，按钮区域标了 `data-interactive`，鼠标移上去窗口就接收点击。
- **只认角色窗口**：主进程的 `chat:confirm` 只接受角色窗口发来的回答，设置窗口和别的页面替不了用户点头。

### 工作窗口（编程 Agent）

- **第四个窗口**，同一个页面地址带 `#/agent` 时加载。会话、事件都来自 AI 服务的 `/agent` 接口（运行时在 aila-ai 里，和终端版 `aila` 是同一个），主进程转发（`main/agent.ts`）：事件流由主进程收、再发给窗口，渲染层不用放开 CSP。
- **只认工作窗口**：主进程的 `agent:*` 只接受工作窗口发来的请求（别的窗口调用返回「只有工作窗口能用」），会话 id、权限模式、长度都检查一遍。
- **事件折叠**（`fold.ts`）：逐字的文字拼成一段，一步结束时用完整文字校正；工具卡片在第一次出现时（要确认、开始、出结果，哪个先到算哪个）加进去，之后原地更新；补发和实时重叠的事件按 seq 去重；工具调用 id 按「第几轮 + id」区分（有的模型每轮都从 call_0 编号，曾经把上一轮的卡片改掉）。
- **关了窗口任务不停**：AI 服务那边照样做完，主进程还在收事件，做完她在桌面上说一声。重新打开窗口时补发日志、接上正在做的任务；终端里开的会话一样能接上。
- **她怎么汇报**：主进程把「开始 / 要确认 / 做完 / 停下 / 出错」转给角色窗口，她做动作、说一句（出声跟着「出声说话」开关）。正在和你对话或者等你回答时不插嘴；她自己念的上一句台词可以被新的进展盖掉。
- **编程用的模型**在「设置 → 对话」里单独设（留空 = 和对话一样），从下一轮起生效。
- **没密钥也能看全流程**：对假模型说「演示改文件」，她会列待办 → 读 README → 改之前问你 → 改 → 看 `git diff` → 打勾，界面上每种卡片都能看到。对话里说「编程任务：在 项目名 里演示改文件」能连对话开任务这一段一起看。
- **从别处交过来的任务**：角色窗口（屏幕上的报错「交给她修」）和星图（「让她修」）经主进程 `agent:task` 调 AI 服务的 `/agent/tasks`，开好就打开工作窗口接上；对话里她用「编程任务」技能包开的任务，对话事件流里有一条 `agent_task`，主进程看到就打开工作窗口。只接受角色窗口和星图窗口发来的。
- **星图看得到她在干活**：主进程转发事件时顺便看她碰了哪个文件（读文件的工具开始时、改文件的结果出来时），发给星图；星图把路径对到当前项目的星球上（Windows 上不分大小写和斜杠方向），读的闪一圈、改过的变绿。工作窗口里等确认的改文件操作也交给星图显示，双手合十由主进程直接回答 AI 服务（id 要对得上正等着的那个）。
- **执行轨迹**（`agent/trace.ts`，纯逻辑有测试）：从会话日志算出来，不用另外记——事件的 `t`、每一步的 `timing`（多久出第一个字、一共多久）、每个工具的 `seconds`，加上确认的开始和结束；正在做的一轮每秒往右长。**上下文账本**由 AI 服务算（它知道系统提示词和工具列表多大），每一步结束、换会话、压缩以后重新取。
- **在新分支上做**：新任务时可以勾；头上显示分支名，右边有「跑测试并合并」「放弃分支」，合并结果在过程里单独一张卡片（测试没过时带失败的输出）。分支放弃后这个会话不再接任务，免得她接着在你真正的项目里改。

### 代码星图（魔法工作台）

- **第三个窗口**：同一个页面，地址带 `#/workbench` 时加载星图（深色、大窗口）；3D 代码只在这个窗口里按需加载。数据（图、函数列表、代码、报错定位）经主进程从 AI 服务取；浏览器里调试（`npm run dev:web` 打开 `#/workbench`）时经 Vite 代理直接取，不用开 Electron 也能看。
- **自己画，不用 3d-force-graph**：它要求 three ≥ 0.179，而 VRM 角色用的是 0.169，装上会打包两份 three，两份的对象不能混用（泛光就用不了）。所以用 d3-force-3d 做力导向布局、项目里已有的 three 画：星球是球体加叠加发光的光晕，光线是一批线段（一次绘制），光点是一批点（一次绘制，沿调用方向流动），最后过一遍泛光（UnrealBloom）。每个子项目被拉向自己的「星系」中心；先在后台排 300 步再显示，稳定后（用户没动过镜头的话）重新取一次景。
- **名字用 HTML 叠在上面**（CSS2DRenderer）：字清楚，也不会被泛光糊掉；放在单独的层里，不会盖住面板。
- **两个踩过的坑**：背景色要设在场景上（`scene.background`），用 `setClearColor` 的话最后输出时又转一次 sRGB，深色背景会发灰；泛光门槛不能太低，否则整个画面发灰。
- **和屏幕感知、修代码连起来**：看到报错时角色窗口在后台问一下报错落不落在登记的项目里，落在了气泡里多一个「在星图里看」（她的问题还留着）。星图里点「问她」「让她修」，经主进程交给角色窗口当成用户说的一句话（主进程只认星图窗口发来的）。
- 纯数据的部分（颜色、大小、星系位置、搜索、报错时哪些星球和光线要亮）在 `layout.ts`，有单元测试。

### 手势

- **只在本机算**：MediaPipe 的手部关键点模型（`npm run setup:gestures` 下载到 `public/mediapipe`）在渲染进程里用 GPU 跑，每秒最多 30 次；窗口看不见时不识别。摄像头只在点了「✋ 手势」以后打开，不记住开关（免得一打开星图摄像头就亮），关掉开关或关掉星图就释放摄像头。
- **从关键点认手势**：所有距离都除以手的大小（手腕到中指根），手离摄像头远近不影响。手指伸直 = 指尖离手腕比第二个关节远；捏合 = 拇指尖靠近食指尖；剑指 = 食指中指伸直且并拢；合十 = 两只手掌和指尖都靠在一起。坐标左右镜像，和屏幕方向一致。
- **防误触**：一次性的手势（唤出、收起、合十、抓住）要保持一小会儿才算，光标上的进度圈显示还差多少；触发后要换个手势才能再触发，还有 1.2 秒冷却。连续的手势（旋转、缩放）有死区，手抖不会让星图跟着抖。光标做了平滑，画面中间 70% 的范围就对应整个窗口（手不用伸到画面边上）。
- **合十确认只认修代码**：角色窗口把「等你确认的代码修改」（id 和 diff）报告给主进程，星图显示同一份 diff；合十时星图带上这个 id，主进程只认星图窗口发来的、而且 id 对得上才转给角色窗口，由角色窗口去回答「好」。打开网页、提交表单这类确认合十不能代答。没有等确认的修改时，合十 = 「让她修」正在显示的报错。
- **特效自己画**：法阵是几层同心环（带刻度）、八角星和小圆，各层往不同方向转；结印是金色光环往外扩。都是正对镜头的线条和薄环，叠加发光、过泛光。
- **不开摄像头也能调试**：开发模式下星图窗口控制台有 `__wb.gesture({ type: 'summon' })`（也可以是 seal、grab、pull、rotate、zoom、dismiss）和 `__wb.setFix({ id, detail })`；手势识别和状态机的单元测试用拼出来的手部关键点。

### 留意屏幕上的报错

- **桌面端只管开关和提问**：截图、识别、判断都在 AI 服务（见 aila-ai 的 README）。角色窗口的 `ScreenWatch` 连着 `/screen`，开关打开才连、发 `start`；关掉就发 `stop` 并断开，程序退出连接自然断开，AI 服务随之停下。AI 服务重启了会自动重连；这台电脑看不了（不是 Windows、缺组件）就告诉用户原因，不再反复重连。
- **开关存在本机**：要不要看屏幕每台电脑单独决定，不跟账号同步；默认关闭。开关和语音开关一样存在角色窗口里，右键菜单、设置窗口（技能包页）经主进程读写。
- **不打断她说话**：她正在回复、或者在等别的确认时看到的报错，先存着，说完再问。问的时候气泡一直显示（45 秒没回答就收起，不算拒绝），按钮是「好 / 不用 / 一小时内别提醒」；也可以在对话框里打「好」「不用」，打别的话就当这次不问了。
- **同意了才发**：点「好」才把报错附近的几行（AI 服务已经打过码）连同是哪个程序、哪个窗口，作为一句话发给大模型；气泡里会写明要发几行。

### 记忆和设置

- **记忆在主进程**：和聊天记录一样存在本地（`memories.json`）、经云端同步；每次对话主进程把记忆附在请求里交给 AI 服务挑相关的。她说完一轮后，记忆管家等 1.5 秒（你可能马上接着说），把最近三轮对话交给 AI 服务整理，按返回的操作更新记忆；同一轮不重复整理，AI 服务没开时这轮就不记，不打扰你。
- **删除优先**：云端说删了，本地哪怕有没传上去的修改也一起删；上传修改时云端返回 410（已经删了），就放弃本地的修改。用户在一台电脑上让她忘掉的事，不会被另一台电脑复活。
- **设置窗口是第二个窗口**：加载同一个页面，按地址决定显示角色还是设置；两边的全局样式不一样（角色窗口全透明），所以入口按需加载。状态变化（同步、记忆、语音开关）由主进程广播给两个窗口；语音开关存在角色窗口里，设置窗口经主进程读写。
- **设置窗口碰不到密钥原文**：读设置时 AI 服务只返回「设没设」；「在文件夹里显示」只认几个固定的名字（配置、模型、数据），路径由主进程问 AI 服务，渲染层不能指定任意路径，打开时也只在资源管理器里定位，不会执行文件。

### 语音

- **按句合成，第一句切短**：回复边收边切句，第一句遇到逗号就切（至少 4 个字），合成好立刻播放；播当前句时后一句已经在合成。所以开口时间只取决于第一句，后面不会停顿等待。
- **文字跟着声音走**：一句的字按这句声音的长度逐字显示（比声音稍快一点），表情、动作标签在说到那里时触发；合成失败的句子退回打字节奏，不会卡住。
- **口型由声音驱动**：播放时用 AnalyserNode 取音量和频谱，音量决定张多大，中频强偏「啊」、高频强偏「衣」「诶」、低频强偏「乌」「哦」，驱动 VRM 的五个元音口型。没出声时还是原来的假口型。
- **回声分两层挡**：麦克风开着浏览器自带的回声消除，她自己的声音基本进不来；万一漏进来，识别结果和她最近说的两句比较，六成以上的字对得上就当回声忽略。只在她说话时和刚说完 1.2 秒内检查，免得把你说的「好的」当成回声。
- **插话先压低音量再停**：她说话时听到你开口，先把音量压到 25%，等识别结果出来确认是在说话才打断；咳嗽、语气词之类的会恢复音量接着说。被打断时历史里只记已经说出口的半句。
- **会话状态在桌面端**：AI 服务只管「听」（等唤醒词 / 断句识别），什么时候回到等唤醒词由桌面端决定，因为只有它知道她是不是还在说话、你是不是还在追问。
- **延迟统计**：每次记录「说完到开口」并拆成断句等待、识别、大模型和首句合成三段，控制台打印；`__aila.voice.latencySummary()` 给出 P50 / P95。
- **不开麦克风也能调试**：开发模式下控制台执行 `__aila.hear('你好艾拉，明天天气怎么样')`，用她自己的合成声音模拟你说话，整条链路（唤醒 → 断句 → 识别 → 对话 → 合成 → 播放 → 口型）照常走一遍。

## 已知待验证

- 手势：只用合成的视频验证过模型加载和整条流程，还没用真摄像头和真手测过各手势的识别率、阈值（`classify.ts` 里的几个数）可能要按实际调。

- 放下手臂的角度（`VrmAvatar.ts` 里的 `1.2`）已在 VRM 1.0（`sample.vrm`）和 VRM 0.x（`Vita.vrm`）上验证，手臂自然下垂；体型差别大的模型可能还要微调。
- 表情名按大小写不敏感匹配（VRoid 0.x 模型的惊讶表情叫 `Surprised`）。
