# 艾拉 · 程序员的 AI 桌面伙伴

常驻桌面的 3D 数字人助手。当前进度：**第 1–3 周完成**——透明桌面窗口、角色渲染、待机动作、点击互动、拖动；和她打字或说话聊天，她出声回答，口型、表情和动作跟着声音走，说话时可以随时插话打断。

## 运行

对话和语音要先启动本地 AI 服务（在旁边的 `aila-ai` 目录，见它的 README，语音模型要先下载）：

```powershell
cd ..\aila-ai
.venv\Scripts\python -m app   # 127.0.0.1:8765；没填密钥时用假模型
```

然后启动桌面端：

```bash
npm install
npm run dev        # 启动桌面版（Electron）
npm run dev:web    # 只在浏览器里调试角色、行为、对话和语音，地址 http://localhost:5180
npm test           # 单元测试（切句、口型、回声判断、语音会话）
npm run typecheck  # 类型检查
npm run build      # 打包到 out/
```

## 怎么玩

| 操作 | 艾拉的反应 |
| --- | --- |
| 双击她 / `Alt+Shift+A` / 右键「和她说话」 | 打开对话框；Enter 发送，Esc 收起 |
| 和她聊天 | 她出声回答，文字跟着声音一个字一个字出现，口型跟着声音变；表情和动作在说到那句话时触发 |
| 她说话时再发一句 | 打断她，直接回答新的问题 |
| 右键勾选「语音唤醒」后说「你好艾拉」 | 她抬头点头，开始听；可以一口气说完「你好艾拉，明天天气怎么样」，也可以叫完名字等她回应 |
| `Alt+Shift+V` / 右键「听我说」 | 不用唤醒词，直接开始听 |
| 她说完后接着说 | 6 秒内可以直接追问，不用再叫她 |
| 她说话时开口 | 她先把声音压低，听清你在说话就停下来听你说；只是咳嗽一声的话会接着说 |
| 右键取消「出声说话」 | 只打字，不出声 |
| 移动鼠标 | 眼睛和头跟着鼠标转（整个屏幕范围） |
| 点她的头 | 缩一下、害羞地低头歪头；连续戳会有不同台词 |
| 点她的身体 | 吓一跳往后仰 |
| 按住拖动 | 身体跟着晃；松手后靠近屏幕边缘会自动贴边 |
| 8 秒不动鼠标 | 开始东张西望 |
| 5 分钟不动鼠标 | 犯困低头；动一下鼠标会惊醒 |
| 右键她 | 菜单：和她说话、听我说、语音唤醒、出声说话、加载 VRM 模型、回到右下角、开发者工具、退出 |

语音唤醒默认关闭：打开后麦克风一直开着（声音只送到本机的 aila-ai，不出这台电脑），所以要你自己决定。

她能做的表情：开心、难过、惊讶、放松；动作：点头、摇头、歪头、思考、鞠躬。由大模型在回复里用标签决定（`[happy]`、`[nod]`），解析在 `aila-ai` 里做。

角色以外的透明区域会让鼠标穿透到桌面，不影响正常使用电脑。

## 换成正式形象

1. 用免费的 [VRoid Studio](https://vroid.com/studio) 捏一个角色，导出为 `.vrm`
2. 右键艾拉 → 加载 VRM 模型
3. 下次启动会自动加载上次的模型

没有模型时显示简易占位角色，所有互动照常可用。

## 几个设计点

- **鼠标穿透**：窗口默认穿透；渲染层读取鼠标下那个像素的透明度，落在角色身上才接收点击。比射线检测更便宜，也不受模型面数影响。
- **视线跟随整个屏幕**：窗口外的鼠标事件收不到，所以主进程每 33ms 轮询一次全局光标位置，推给渲染层。
- **行为和渲染分离**：`Behavior` 只算表情权重和姿态参数，角色实现只负责画出来。占位角色和 VRM 角色共用同一套行为。
- **平滑过渡**：所有表情和姿态都用和帧率无关的指数平滑，动作之间不会跳变。
- **动作和那句话同步**：网络一次可能来好几个字，也可能卡一下。回复先进队列，再按固定节奏（每秒 18 字，句号后停顿）放出来；标签排在文字中间，放到那里才触发。所以「[nod]今天也请多指教」一定是说到这句时才点头。
- **对话请求走主进程**：渲染层不用放开 CSP 和跨域，打包成 `file://` 后也一样能用；浏览器调试时走 Vite 代理，两条路共用同一套 SSE 解析。语音合成同样走主进程；语音的 WebSocket 不受跨域限制，由渲染层直接连，AI 服务检查 Origin。麦克风权限只给自己的页面。
- **一定有结局**：AI 服务没开、密钥错、余额不足、中途断开，都会归类成不同的错误，艾拉用不同的话回应，不会卡在「……」。
- **打断只记已说出口的部分**：被新消息打断时，历史里只存已经显示出来的那段，大模型不会以为用户听完了整句话（第 3 周语音打断也靠这个）。
- **搜索进度也排队**：AI 服务在调用工具前推一个 `status` 事件，它和文字排在同一个队列里，等「我查一下」说完才在气泡最后一行显示「（正在搜索「…」……）」，她同时摆出思考的样子；下一句开口时清掉。进度不算说出口的话，不进历史。

### 语音

- **按句合成，第一句切短**：回复边收边切句，第一句遇到逗号就切（至少 4 个字），合成好立刻播放；播当前句时后一句已经在合成。所以开口时间只取决于第一句，后面不会停顿等待。
- **文字跟着声音走**：一句的字按这句声音的长度逐字显示（比声音稍快一点），表情、动作标签在说到那里时触发；合成失败的句子退回打字节奏，不会卡住。
- **口型由声音驱动**：播放时用 AnalyserNode 取音量和频谱，音量决定张多大，中频强偏「啊」、高频强偏「衣」「诶」、低频强偏「乌」「哦」，驱动 VRM 的五个元音口型。没出声时还是原来的假口型。
- **回声分两层挡**：麦克风开着浏览器自带的回声消除，她自己的声音基本进不来；万一漏进来，识别结果和她最近说的两句比较，六成以上的字对得上就当回声忽略。只在她说话时和刚说完 1.2 秒内检查，免得把你说的「好的」当成回声。
- **插话先压低音量再停**：她说话时听到你开口，先把音量压到 25%，等识别结果出来确认是在说话才打断；咳嗽、语气词之类的会恢复音量接着说。被打断时历史里只记已经说出口的半句。
- **会话状态在桌面端**：AI 服务只管「听」（等唤醒词 / 断句识别），什么时候回到等唤醒词由桌面端决定，因为只有它知道她是不是还在说话、你是不是还在追问。
- **延迟统计**：每次记录「说完到开口」并拆成断句等待、识别、大模型和首句合成三段，控制台打印；`__aila.voice.latencySummary()` 给出 P50 / P95。
- **不开麦克风也能调试**：开发模式下控制台执行 `__aila.hear('你好艾拉，明天天气怎么样')`，用她自己的合成声音模拟你说话，整条链路（唤醒 → 断句 → 识别 → 对话 → 合成 → 播放 → 口型）照常走一遍。

## 已知待验证
