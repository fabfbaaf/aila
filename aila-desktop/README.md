# 艾拉 · 程序员的 AI 桌面伙伴

常驻桌面的 3D 数字人助手。当前进度：**第 1–5 周完成**——透明桌面窗口、角色渲染、待机动作、点击互动、拖动；和她打字或说话聊天，她出声回答，口型、表情和动作跟着声音走，说话时可以随时插话打断；她会记住你说过的事，能翻你放进来的资料；聊天记录和记忆登录后在几台电脑之间同步；所有设置集中在一个设置窗口里。

## 运行

开发时桌面端会自己启动旁边的 `aila-ai`，不需要另开服务终端。先在 `aila-ai` 里建好虚拟环境和依赖（语音模型见它的 README）：

```powershell
cd ..\aila-ai
py -3.12 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

回到 `aila-desktop` 启动桌面端：

```bash
npm install
npm run dev        # 启动桌面版（Electron）
npm run dev:web    # 只在浏览器里调试角色、行为、对话和语音，地址 http://localhost:5180
npm run setup:gestures  # 手势要用：把 MediaPipe 的识别程序和手部模型放到 public/mediapipe（一次就行，约 35MB，不进 git）
npm test           # 单元测试（切句、口型、回声判断、语音会话、同步引擎、记忆）
npm run typecheck  # 类型检查
npm run build      # 打包到 out/
```

设置 →「运行状态」最上面的「AI 服务」卡片可以看状态、进程号、最近 200 行日志，或者手动重启。第一次加载模型最多等 60 秒；服务崩溃后按 1、3、9 秒重试，5 分钟内用完 3 次重试会暂停，查看日志后点「重启服务」。退出应用会结束自己开的服务和它的子进程，关闭主窗口则继续运行。

想直接看服务终端输出时，仍可先在 `aila-ai` 里运行 `.venv\Scripts\python -m app`。桌面端检测到后显示「别人开的」，不重启它，退出时也不关它。`npm run dev:web` 只是浏览器页面，没有主进程托管，需要自己启动服务。

服务目录或 Python 在别处时，设置 `AILA_AI_DIR`、`AILA_AI_PYTHON`。`AILA_AI_URL` 可改地址和端口，托管进程会使用这个地址的 host 和 port；健康检查不会经过系统代理。安装包里用自带的 `resources\aila-ai\aila-ai.exe`（见下面「打包」）；开发时找不到服务，卡片会显示建虚拟环境的说明。日志不枚举环境变量，常见密钥写法会隐藏；不要让服务主动输出敏感信息。

## 打包

**正式安装包**（别的电脑双击就能装，不用装 Python、Node）：

```powershell
# 1. 先把 AI 服务打成一个目录（带 Python）：aila-ai\dist\aila-ai\aila-ai.exe，打完自己冒烟测试
cd ..\aila-ai
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python scripts\build_service.py

# 2. 再打安装包：生成图标、构建、用 electron-builder 打 NSIS
cd ..\aila-desktop
npm.cmd run dist
```

产物在 `dist\installer\艾拉 Setup 0.1.0.exe`，约 260MB（装好后约 800MB；AI 服务目录约 500MB，大头是文字识别用的 OpenCV 和浏览器驱动）。第一次打包时 electron-builder 会从它的 GitHub 发布页下载 NSIS 和改图标的工具，之后用缓存。

- 装给当前用户，不用管理员权限；开始菜单和桌面有「艾拉」快捷方式。图标是 `scripts/make-icon.mjs` 用代码画的（和托盘一样的紫色圆环）
- 用户的东西都不写安装目录：大模型密钥（`.env`）、会话、记忆、代码索引、下载的语音模型都在 `%APPDATA%\aila-desktop\ai\` 下面（`AILA_ENV_FILE`、`AILA_DATA_DIR`、`AILA_MODELS_DIR`、`AILA_MCP_CONFIG` 由桌面端指过去，见 `main/serviceNode.ts` 的 `packagedCommand`）。桌面端自己的设置、登录、聊天记录在 `%APPDATA%\aila-desktop` 本身，和开发时、本机测试版是同一个文件夹；AI 服务那边的不一样（开发时用仓库 `aila-ai` 里的 `.env` 和 `data\`），所以在开发的电脑上装了安装包，要在设置里重新填一次密钥
- 语音模型不放进安装包（约 460MB）：「设置 → 语音」里点「下载语音模型」，下完 AI 服务自动重启一次
- 开发用的 VRM 示例模型不打进去，她用自带的原创形象
- 没有代码签名证书：Windows 会弹「已保护你的电脑」，点「更多信息 → 仍要运行」
- 卸载会删掉安装目录，`%APPDATA%\aila-desktop` 留着（下次装还在）。要彻底删：卸载后再删掉这个文件夹

**本机测试版**（`npm.cmd run pack:local`）：只打桌面端，AI 服务用这台电脑上仓库里的虚拟环境，所以只能在这台电脑上用；打得快，适合自己试。

| 星图里点「✋ 手势」 | 打开摄像头用手势操作（只在这台电脑上识别，不保存、不上传）：张开手掌移动旋转、双手拉开合拢缩放、剑指保持一下唤出全图（法阵特效）、捏住一颗星球往面前拉展开它的代码、握拳收起面板（没有面板就关掉星图）；她准备好代码修改时星图里也显示那份 diff，双手合十保持一秒确认 |
| 屏幕上看到报错时点「在星图里看」 | 星图里出错的文件变红、一跳一跳，往上的调用链变橙，镜头飞过去，面板里出错那一行标红；点「让她修」在工作窗口里开任务修它 |
| 屏幕上看到报错时点「交给她修」 | 报错落在登记的项目里时才有这个按钮：在那个项目里开一个修报错的任务，工作窗口打开、她开始做（改文件之前照样问你） |
| 对她说「编程任务：在 aila 里给购物车加个打折函数」 | 打字或者说话都行：她不在对话里写代码，而是在工作窗口里开任务去做（按名字找项目，有好几个就先问你是哪个） |
| 工作窗口里做任务时开着星图 | 她读的文件在星图上闪一圈青光，改过的变绿、显示名字，底下一行「她正在读 / 改 xx」；要你确认的改文件操作星图里也显示 diff，双手合十就是「可以」 |
| 工作窗口顶上点「轨迹」 | 每一轮一条时间线：她在想（浅色是等第一个字）、每个工具、等你确认各一行，带用时和每一步命中多少缓存，下面列出最慢的几步 |
| 工作窗口右边「上下文账本」 | 下一步发给模型的上下文由哪几块组成：整个窗口一条横条（黄线是压缩线）、用掉的部分各块的比例、开头固定命中缓存的有多少、最占地方的几个工具结果、每一步的缓存命中 |
| 新任务时勾「在新分支上做」 | 她在一个临时的 git 分支里改，你的代码一个字不动；右边「跑测试并合并」：测试全过、你这期间没改过同样的文件，才写回你的代码（不替你提交）；没找到测试命令时可以选「不跑测试直接合并」；「放弃分支」删得干干净净 |
| 「帮我修好它」 | 气泡里先给你看 diff（加的行绿、删的行红）和要跑的测试；点「好」后她在新分支上改、跑测试，全过才改到你的代码里，没过自动撤回（要接上真大模型） |
| 右键「留意屏幕上的报错」 | 她每 2 秒看一眼前台窗口（只看编辑器、IDE、终端），看到报错问你「要我帮你看看吗？」：「好」就把那几行报错交给大模型；「不用」；「一小时内别提醒」。开着时脚边显示「正在看屏幕」，默认关闭 |
| 「去 GitHub 上搜一下 three-vrm」 | 她开一个自己的 Edge 窗口去搜（你看得到）；点普通链接、搜索直接做，点其他按钮、提交表单前先问你；密码、验证码让你自己填（要接上真大模型） |
| 重启程序 | 她还记得刚才聊到哪了（最近 40 句带给大模型） |
| 右键她 | 菜单：和她说话、听我说、语音唤醒、出声说话、留意屏幕上的报错、技能包、打开艾拉、项目和地图、资料库、她记得的事、设置、回到右下角、开发者工具、退出 |

### 主窗口「艾拉」

普通的窗口（可以调大小），和桌面上透明的她分开。以前的工作窗口、代码星图、设置三个窗口都合进来了，左边一列图标切页面（`Ctrl+1`…`Ctrl+7`）：

| 页面 | 是什么 |
| --- | --- |
| 任务 | 原来的工作窗口：给她编程任务、看她每一步、回答确认 |
| 对话 | 和她聊过的话，按天排、能搜（记录本来就存在本机、登录后同步，这一页只是摆出来看）；「和她说话」在桌面上打开对话框 |
| 项目 | 列表：登记项目、看索引状态（原来的「设置 → 代码库」）；地图：原来的代码星图，只在看的时候才画 |
| 资料 | 资料库 |
| 记忆 | 她记得的事 |
| 作品 | 她自己做的小作品（网页的能直接打开玩）和她的日记 |
| 设置 | 下面这些分区 |

关掉主窗口任务照样做；托盘图标随时能打开它。设置页的分区：

| 分区 | 能改什么 |
| --- | --- |
| 对话 | 大模型地址、模型、密钥（「测试连接」看对不对）；搜索服务和密钥。保存后立刻生效，写进 `aila-ai/.env` |
| 语音 | 语音唤醒、出声说话；声音引擎、语速（可以试听）；唤醒灵敏度、说完的判定停顿、识别语种 |
| 技能包 | 每个技能包的开关、有哪些工具、哪些要你确认；外部 MCP 服务的连接状态 |
| 资料库 | 添加、删除文档（只保存在这台电脑上） |
| 代码库 | 登记项目文件夹（主进程弹窗选，渲染层不能指定任意路径）、看索引进度和统计、重新扫描、不再登记 |
| 她记得的事 | 按类别列出，单条删除，或全部忘掉 |
| 账号与同步 | 登录、注册、退出；同步状态；登录着的电脑 |
| 形象 | 选 VRM 模型；让她回到右下角 |
| 运行状态 | 各个模型有没有准备好；配置、模型、数据文件在哪 |

密钥只能填不能看：保存后界面只显示「已设置」。在设置窗口里删记忆、加资料，桌面上的她会有反应。

语音唤醒默认关闭：打开后麦克风一直开着（声音只送到本机的 aila-ai，不出这台电脑），所以要你自己决定。

不登录也能用，聊天记录只存在这台电脑上。登录时，登录前的记录会并入账号；退出登录时清空本机的记录（云端的还在），换个账号登录也不会把上一个人的记录传过去。「出声说话」会跟着账号同步，「语音唤醒」因为要开麦克风，每台电脑单独决定。

她能做的表情：开心、难过、惊讶、放松；动作：点头、摇头、歪头、思考、鞠躬。由大模型在回复里用标签决定（`[happy]`、`[nod]`），解析在 `aila-ai` 里做。

角色以外的透明区域会让鼠标穿透到桌面，不影响正常使用电脑。

## 她的形象

默认是她自己的原创形象 `src/renderer/public/avatar/aila.vrm`（VRM 1.0，约 2MB），由 `scripts/avatar/make-avatar.mjs` 用代码一块块搭出来，进 Git、随程序自带：

- 短短的银紫色波波头、刘海和两缕鬓发、一撮呆毛；紫灰色的大眼睛跟着鼠标转
- 宽松的米白连帽卫衣（长袖、浅紫袖口）、藏青百褶裙、深色长袜、白色运动鞋
- 只属于她的两个细节：右边头发上的紫色「▍」光标发夹，卫衣左胸的「>_」终端提示符

## 几个设计点

- **鼠标穿透**：窗口默认穿透；渲染层读取鼠标下那个像素的透明度，落在角色身上才接收点击。比射线检测更便宜，也不受模型面数影响。
- **视线跟随整个屏幕**：窗口外的鼠标事件收不到，所以主进程每 33ms 轮询一次全局光标位置，推给渲染层。
- **行为和渲染分离**：`Behavior` 只算表情权重和姿态参数，角色实现只负责画出来。占位角色和 VRM 角色共用同一套行为。
- **平滑过渡**：所有表情和姿态都用和帧率无关的指数平滑，动作之间不会跳变。
- **动作和那句话同步**：网络一次可能来好几个字，也可能卡一下。回复先进队列，再按固定节奏（每秒 18 字，句号后停顿）放出来；标签排在文字中间，放到那里才触发。所以「[nod]今天也请多指教」一定是说到这句时才点头。
- **对话请求走主进程**：渲染层不用放开 CSP 和跨域，打包成 `file://` 后也一样能用；浏览器调试时走 Vite 代理，两条路共用同一套 SSE 解析。语音合成同样走主进程；语音的 WebSocket 不受跨域限制，由渲染层直接连，AI 服务检查 Origin。麦克风权限只给自己的页面。

### 同步

- **同步在主进程**：令牌、本地记录、和云端的连接都在主进程，渲染层只拿到对话记录和状态，碰不到令牌。
- **先存本地，再上传**：每条消息带着本地生成的 UUID 存进 `history.json`，没有序号的就是还没传上去的。正常结束的回复保存全文，断网时攒着，连上后补传；UUID 保证重传不会重复。
- **推送只是提醒，数据靠拉**：WebSocket 只告诉「最新序号是 N」，比本地大就按 `since` 分页拉取。每次重连服务端先发 hello 带上最新序号，所以断线期间漏掉的推送不影响，重连后自动补齐。
- **连接自己会恢复**：断线后按 1、2、4……30 秒退避重连，带随机抖动（服务端重启后客户端不会同时涌上来）；每 25 秒心跳一次，10 秒没回应就主动断开重连（电脑睡眠醒来后不会挂着一条死连接）。
- **令牌**：访问令牌只在内存里；刷新令牌用 Electron 的 `safeStorage` 加密保存（Windows 上是 DPAPI，只有当前系统用户能解开）。刷新是「单飞」的：好几个请求同时发现令牌过期，也只刷新一次，因为服务端发现同一个刷新令牌被用两次会当成被盗，整个登录作废。
- **端到端测试**：`src/main/cloud/sync.e2e.test.ts` 连真服务器，两台「设备」互发消息、断线补齐（先启动 `aila-server`，设置 `AILA_SERVER_E2E=http://127.0.0.1:8790` 再跑）。开发时设置 `AILA_REMOTE_DEBUG=端口` 会打开远程调试，可以用脚本通过 Chrome 调试协议驱动真实窗口（打包后无效）。
- **一定有结局**：AI 服务没开、密钥错、余额不足、中途断开，都会归类成不同的错误，艾拉用不同的话回应，不会卡在「……」。
- **打断按回复收齐与否保存**：AI 服务还没发完时被新消息打断，历史里只存已经显示出来的那段。服务已发完全文、摘要仍在播放时被打断，历史仍保留完整文字。
- **搜索进度也排队**：AI 服务在调用工具前推一个 `status` 事件，它和文字排在同一个队列里，等「我查一下」说完才在气泡最后一行显示「（正在搜索「…」……）」，她同时摆出思考的样子；下一句开口时清掉。进度不算说出口的话，不进历史。

### 操作确认

- **问完再出按钮**：AI 服务推来 `confirm` 事件时，她先说一句「……要我{要做的事}吗？」（和平常说话一样打字或出声），说完才在气泡下方显示具体内容和「好 / 不要」。具体内容（比如完整网址）只显示不念，照 AI 服务给的原样显示，不经过大模型改写。
- **三种回答方式**：点按钮；在对话框里打字；语音会话中直接说。打字和说的话先过 `confirmIntent`：整句都是「好、可以、嗯、打开吧」这类词才算同意，短句里带「不、别、算了、取消」算不同意，其他话（问别的事、太长）不算回答，照常当新的一句话发出去——这会打断当前回复，操作随之作废。宁可认不出，也不能把「是什么网站？」认成同意。
- **按钮能点**：窗口平时只在角色身上接收鼠标，按钮区域标了 `data-interactive`，鼠标移上去窗口就接收点击。
- **只认角色窗口**：主进程的 `chat:confirm` 只接受角色窗口发来的回答，设置窗口和别的页面替不了用户点头。

### 任务页（编程 Agent）

- **让她在浏览器里验收网页**：改完前端，可以让她起开发服务器、打开页面试一下并截图。第一次打开本机的某个端口会在卡片里问你，可以选「这个项目里这个端口以后都不用问」。点截图卡片的「看截图」，直接在任务过程里看页面。浏览器调试版可以看工具文字，图片预览在桌面端。
- **会话列表**：按今天 / 昨天 / 这周 / 更早分组（`agent/sessions.ts`）；上面的搜索框按标题或项目路径找（服务端先筛再限数量，很早的会话也找得到）；每一项右边「⋯」能改名、删除。删除前的说明由代码按会话情况生成（在分支上做的会说临时目录会一起放弃），她还在做的会话要先打断
- **外部工具（MCP）**：设置页 → 编程 → 外部工具（MCP）。贴服务说明里的配置（Claude Desktop 的 `mcpServers` 写法），先点「检查」看要在这台电脑上启动的命令（AI 服务从配置拼出来的），再「保存并启动」；能看状态、工具（哪些只读、哪些设了以后都不问）、没起来时的日志，能重启、停用、删除（删除要点两下），撤销「以后都不用问」。环境变量只显示名字。IPC `agent:mcp*` 只认主窗口。浏览器里调试时 `AILA_AI_URL` 能把 `/ai` 代理指到别的端口（`.claude/launch.json` 的 `aila-web-alt` 用 8766）
- **项目记忆**：右边一栏的「项目记忆」列出她在这个项目里记下的约定（紫点是她记的，青点是你加的），能删，也能自己加一条；改动从下一个任务起放进开头。她在任务里记了新的，这里马上更新。IPC `agent:memory*` 只认主窗口
- **「等你」收件箱**：会话列表里标出在等你的任务（「等你确认」「等你看计划」「计划停了」），按计划做的标「第 2/4 阶段」；主窗口图标栏「任务」上有个数字角标，数的是在等你的任务。列表每 15 秒刷新一次（终端里开的任务也算）。桌面上的她在有操作要你同意时，气泡里多一个「去看看」，点了打开那个任务——同意还是在任务页里点，那里看得到完整的改动或命令
- **长任务**：输入框下面的「出方案」（或输入 `/plan 目标`、新任务里勾「先出方案再动手」）。她先只读地交一份分阶段的计划，显示成计划卡片（每阶段的目标、怎么验收）：「照这个做」（可以勾「每个阶段做完停一下」）、「不用了」，想改就直接在输入框里说。批准后一阶段一阶段做下去，每阶段开始是一行「▶ 第 1/3 阶段：……」；右边一栏有计划进度，停下时写原因，有「接着做第 N 阶段」。计划状态从日志推出来（`agent/plan.ts`，和 AI 服务的 `plan_state` 同一套规则）。桌面上的她：按计划做时每轮不说「做完了」，一个阶段做完、整个计划做完、计划停下才说
- **电脑任务**：新任务中选「不选项目，操作电脑」，再点「开电脑任务」，从用户目录开始。会话列表和顶栏显示「电脑」；只有只读、先问再改，不能选工作区内自动或新分支。计划卡片、阶段进度、花费上限、撤销一轮和压缩仍可使用。批量操作先列清单和方案，确认后再动；移动、改名和命令的副作用不能靠「撤销这一轮」恢复。通过命令行或脚本接口操作，没有这类接口的程序无法操作。
- **电脑环境说明**：「设置 → 编程」的「告诉她这台电脑装了什么」默认开，只列系统、常用目录、程序名和命令行工具名，不读取文件内容；关掉后只保留系统和常用目录。「看看具体写了什么」在页内展开本机生成的原文，读取失败可以重试。开关只影响新电脑任务，已有任务保留创建时的说明。电脑任务记住的命令在「记住的命令 → 电脑」中查看和删除，单独保存，不和项目混用。
- **对话里的电脑操作**：多步目标先确认「开个电脑任务做」，打开任务页先出方案；一两步的小事可在设置里打开默认关闭的「电脑操作」技能，只读 PowerShell 命令直接跑，其他命令逐条确认，给你看命令原文，不继承电脑任务记住的命令。
- **看板**：侧栏「看板」（数字是在做和等你的任务数）切到看板，几个任务同时做时一眼看全。四栏：等你（要你同意、看计划、计划停下了）、在做（「在改 cart.py」这样一行）、做完了（最近三天，改了几个文件）、卡住了（出错、步数用完、被打断、花费到上限）。卡片上能直接「可以 / 不行」她等着的那个操作（说明是代码按参数生成的，和任务页里的一样；只给不能记住的回答，「以后都允许」要进任务里点）、停下、打开。「一次开几个」：选项目和权限模式，一行写一个任务（最多 6 个），每个都开在新分支上（互不干扰，做完在各自的任务里合并）。看板开着时每 2.5 秒刷新一次列表；后台刷新偶尔失败不提示，下次补上。分栏和那一行字在 `agent/board.ts`；摘要里的 `activity`、`outcome`、`edits`、`pending` 由 AI 服务从会话日志算（`Session.summary`）
- **命令菜单**：输入框里打「/」弹出能用的命令：内置的（/plan、/review、/commit 提交、/pr 开 PR、/pr-comments 按 PR 评论接着改；电脑任务只有 /plan）、项目 `.aila/commands/` 里的、自己的（数据目录 `commands/`）。↑↓ 选，Tab 补全，Enter 补全（已经打全了就发送），Esc 收起。自定义命令在对话里显示成「/发布 v1.2」，点「看发了什么」展开命令文件展开后的全文。筛选和按键规则在 `agent/commands.ts`
- **审查改动**：输入框下面的「审查改动」，或者输入 `/review 要特别注意的地方`。她只读地审一遍没提交的改动，按严重程度列问题；这一轮在列表里只显示「审查没提交的改动 · 只读」一句
- **花费和上限**：新任务可填「花费上限（元，可以不填）」。任务页顶部显示累计花费和上限，点金额在页内修改，留空取消。每轮结束显示本轮的钱；用量包括自动压缩和查资料的助手。价格来自 AI 服务的 `data/prices.json`，格式见 `aila-ai/README.md`「花费和上限」。模型价格未知时保留 token 并提示价格未知，金额不会显示成 0；补齐价格后才能完整约束花费。累计已花达到上限，就在下一步开始前停下，桌面上的她也会说一句。调高上限或取消上限后说「继续」接着做，当前一步和已派出的助手会做完，所以总额可能略超。
- **撤销这一轮**：最新一轮结束、她空闲且这一轮有留底的文件改动时，结尾会出现「撤销这一轮」。点开先看要还原或删除的文件，再确认。结果会列出已恢复和跳过的文件，用户后来改过的文件不动。后台命令和其他命令的副作用不在撤销范围内。在分支会话里撤回的是临时工作目录，已经合并到原项目的内容需要另行处理。
- **主窗口里的一页**（原来是单独的工作窗口）。会话、事件都来自 AI 服务的 `/agent` 接口（运行时在 aila-ai 里，和终端版 `aila` 是同一个），主进程转发（`main/agent.ts`）：事件流由主进程收、再发给窗口，渲染层不用放开 CSP。
- **只认主窗口**：主进程的 `agent:*` 只接受主窗口发来的请求（角色窗口调用返回「只有主窗口能用」），会话 id、权限模式、长度都检查一遍。切到别的页面时任务页还留着，但不再听 `1` / `2` / `Esc`，免得在设置里打字时替你点了「可以」。
- **事件折叠**（`fold.ts`）：逐字的文字拼成一段，一步结束时用完整文字校正；工具卡片在第一次出现时（要确认、开始、出结果，哪个先到算哪个）加进去，之后原地更新；补发和实时重叠的事件按 seq 去重；工具调用 id 按「第几轮 + id」区分（有的模型每轮都从 call_0 编号，曾经把上一轮的卡片改掉）。
- **关了窗口任务不停**：AI 服务那边照样做完，主进程还在收事件，做完她在桌面上说一声。重新打开窗口时补发日志、接上正在做的任务；终端里开的会话一样能接上。
- **她怎么汇报**：主进程把「开始 / 要确认 / 做完 / 停下 / 出错」转给角色窗口，她做动作、说一句（出声跟着「出声说话」开关）。正在和你对话或者等你回答时不插嘴；她自己念的上一句台词可以被新的进展盖掉。
- **编程用的模型**在「设置 → 对话」里单独设（留空 = 和对话一样），从下一轮起生效。
- **派助手去查**：她可以派只读的助手（explore）去翻代码，卡片里是助手的报告和它查了几步；对假模型说「演示查资料」能看到两个助手一起查。
- **没密钥也能看全流程**：对假模型说「演示改文件」，她会列待办 → 读 README → 改之前问你 → 改 → 看 `git diff` → 打勾，界面上每种卡片都能看到。对话里说「编程任务：在 项目名 里演示改文件」能连对话开任务这一段一起看。
- **从别处交过来的任务**：角色窗口（屏幕上的报错「交给她修」）和星图（「让她修」）经主进程 `agent:task` 调 AI 服务的 `/agent/tasks`，开好就打开工作窗口接上；对话里她用「编程任务」技能包开的任务，对话事件流里有一条 `agent_task`，主进程看到就打开工作窗口。只接受角色窗口和星图窗口发来的。
- **星图看得到她在干活**：主进程转发事件时顺便看她碰了哪个文件（读文件的工具开始时、改文件的结果出来时），发给星图；星图把路径对到当前项目的星球上（Windows 上不分大小写和斜杠方向），读的闪一圈、改过的变绿。工作窗口里等确认的改文件操作也交给星图显示，双手合十由主进程直接回答 AI 服务（id 要对得上正等着的那个）。
- **执行轨迹**（`agent/trace.ts`，纯逻辑有测试）：从会话日志算出来，不用另外记——事件的 `t`、每一步的 `timing`（多久出第一个字、一共多久）、每个工具的 `seconds`，加上确认的开始和结束；正在做的一轮每秒往右长。**上下文账本**由 AI 服务算（它知道系统提示词和工具列表多大），每一步结束、换会话、压缩以后重新取。
- **在新分支上做**：新任务时可以勾；头上显示分支名，右边有「跑测试并合并」「放弃分支」，合并结果在过程里单独一张卡片（测试没过时带失败的输出）。分支放弃后这个会话不再接任务，免得她接着在你真正的项目里改。

### 代码星图（魔法工作台）

- **第三个窗口**：同一个页面，地址带 `#/workbench` 时加载星图（深色、大窗口）；3D 代码只在这个窗口里按需加载。数据（图、函数列表、代码、报错定位）经主进程从 AI 服务取；浏览器里调试（`npm run dev:web` 打开 `#/workbench`）时经 Vite 代理直接取，不用开 Electron 也能看。
- **自己画，不用 3d-force-graph**：它要求 three ≥ 0.179，而 VRM 角色用的是 0.169，装上会打包两份 three，两份的对象不能混用（泛光就用不了）。所以用 d3-force-3d 做力导向布局、项目里已有的 three 画：星球是球体加叠加发光的光晕，光线是一批线段（一次绘制），光点是一批点（一次绘制，沿调用方向流动），最后过一遍泛光（UnrealBloom）。每个子项目被拉向自己的「星系」中心；先在后台排 300 步再显示，稳定后（用户没动过镜头的话）重新取一次景。
- **名字用 HTML 叠在上面**（CSS2DRenderer）：字清楚，也不会被泛光糊掉；放在单独的层里，不会盖住面板。每隔几帧按优先级重新摆一遍（星系名 > 报错、选中的文件 > 拉远时的模块名 / 拉近时的文件名，测试文件排最后），挡住的先不显示（`layout.ts` 的 `placeLabels`）。
- **三层：星系 → 模块 → 文件**：同一个目录是一个模块，模块的中心撒在子项目的星系周围（最大的在中间），文件被拉向自己模块的中心。拉远（看全部）时每个模块是一颗带名字的大星，模块之间是汇总后的光线，文件往模块中心收拢、淡下去；拉近到一半左右，大星淡去、散开成一个个文件。远近按镜头距离和「看全部」时的距离之比平滑过渡（`zoomLevel`）。点模块飞过去。模块的名字去掉子项目、`src`、Java 的 `src/main/java` 和大家都有的包前缀（`moduleLabels`）。
- **回放她的一次任务**：顶上「回放」列出这个项目里做过的任务，选一个后底部出时间轴：一步一步重放她读了哪些文件（闪青光）、改了哪里（变绿并一直绿着）、跑了什么命令、这一轮怎么结束的；播放、暂停、1×/2×/4×、拖动（拖动时按到这一步为止改过的文件重新标绿），「镜头跟着走」只平移不缩放。按步播不按真实时间（她想了 20 秒、测试跑了 1 分钟时画面不会干等）。会话日志 → 每一步、对到星球，在 `replay.ts`；任务数据经主进程从 AI 服务取（`agent:list`、`agent:get` 只认主窗口，星图就在主窗口里）
- **换颜色看项目**：图例上方「按子项目 / 按改动 / 按测试」。按改动：最近 300 次提交里每个文件改过几次（AI 服务 `git log --relative --name-only` 数的，图里的 `churn`），从暗蓝（没改过）到青、黄、红，按对数算，图例列出改得最多的 5 个、点一下飞过去；模块按里面最热的文件上色。按测试：测试文件调用了它（任何光线从测试文件连过来）或者有同名测试文件（`test_cart.py` ↔ `cart.py`、`fold.test.ts`、`CartTest.java`）就算有测试——是估算，不用跑覆盖率；绿有、橙红没找到、灰是测试文件本身，模块按有测试的文件占几成从橙红渐变到绿。颜色在 `layout.ts` 的 `modeColors`
- **跨进程的弧线**：函数调用只在同一类语言里连得上，桌面端和 AI 服务、云端之间（HTTP）、预加载和主进程之间（IPC）就成了互不相干的岛。AI 服务扫出谁请求了哪个接口、谁提供它，星图画成往上拱起的弧线（淡金 HTTP、淡青 IPC），光点沿请求方向流动；点文件时面板里列出它请求了谁、谁请求了它，点一下飞过去。
- **测试文件调暗**：颜色往灰色混、光线更暗，顶上可以一键隐藏。
- **星系排在正对镜头的平面上**，没人动时只左右轻轻晃，不转整圈（转到侧面几个星系会前后挡住）。
- **两个踩过的坑**：背景色要设在场景上（`scene.background`），用 `setClearColor` 的话最后输出时又转一次 sRGB，深色背景会发灰；泛光门槛不能太低，否则整个画面发灰。
- **和屏幕感知、修代码连起来**：看到报错时角色窗口在后台问一下报错落不落在登记的项目里，落在了气泡里多一个「在星图里看」（她的问题还留着）。星图里点「问她」「让她修」，经主进程交给角色窗口当成用户说的一句话（主进程只认星图窗口发来的）。
- 纯数据的部分（颜色、大小、星系位置、搜索、报错时哪些星球和光线要亮）在 `layout.ts`，有单元测试。

### 手势

- **只在本机算**：MediaPipe 的手部关键点模型（`npm run setup:gestures` 下载到 `public/mediapipe`）在渲染进程里用 GPU 跑，每秒最多 30 次；窗口看不见时不识别。摄像头只在点了「✋ 手势」以后打开，不记住开关（免得一打开星图摄像头就亮），关掉开关或关掉星图就释放摄像头。
- **从关键点认手势**：所有距离都除以手的大小（手腕到中指根），手离摄像头远近不影响。手指伸直 = 指尖离手腕比第二个关节远；捏合 = 拇指尖靠近食指尖；剑指 = 食指中指伸直且并拢；合十 = 两只手掌和指尖都靠在一起。坐标左右镜像，和屏幕方向一致。
- **防误触**：一次性的手势（唤出、收起、合十、抓住）要保持一小会儿才算，光标上的进度圈显示还差多少；触发后要换个手势才能再触发，还有 1.2 秒冷却。连续的手势（旋转、缩放）有死区，手抖不会让星图跟着抖。光标做了平滑，画面中间 70% 的范围就对应整个窗口（手不用伸到画面边上）。
- **合十确认只认修代码**：角色窗口把「等你确认的代码修改」（id 和 diff）报告给主进程，星图显示同一份 diff；合十时星图带上这个 id，主进程只认星图窗口发来的、而且 id 对得上才转给角色窗口，由角色窗口去回答「好」。打开网页、提交表单这类确认合十不能代答。没有等确认的修改时，合十 = 「让她修」正在显示的报错。
- **特效自己画**：法阵是几层同心环（带刻度）、八角星和小圆，各层往不同方向转；结印是金色光环往外扩。都是正对镜头的线条和薄环，叠加发光、过泛光。
- **不开摄像头也能调试**：开发模式下星图窗口控制台有 `__wb.gesture({ type: 'summon' })`（也可以是 seal、grab、pull、rotate、zoom、dismiss）和 `__wb.setFix({ id, detail })`；手势识别和状态机的单元测试用拼出来的手部关键点。

### 留意屏幕上的报错

- **桌面端只管开关和提问**：截图、识别、判断都在 AI 服务（见 aila-ai 的 README）。角色窗口的 `ScreenWatch` 连着 `/screen`，开关打开才连、发 `start`；关掉就发 `stop` 并断开，程序退出连接自然断开，AI 服务随之停下。AI 服务重启了会自动重连；这台电脑看不了（不是 Windows、缺组件）就告诉用户原因，不再反复重连。
- **开关存在本机**：要不要看屏幕每台电脑单独决定，不跟账号同步；默认关闭。开关和语音开关一样存在角色窗口里，右键菜单、设置窗口（技能包页）经主进程读写。
- **不打断她说话**：她正在回复、或者在等别的确认时看到的报错，先存着，说完再问。问的时候气泡一直显示（45 秒没回答就收起，不算拒绝），按钮是「好 / 不用 / 一小时内别提醒」；也可以在对话框里打「好」「不用」，打别的话就当这次不问了。
- **同意了才发**：点「好」才把报错附近的几行（AI 服务已经打过码）连同是哪个程序、哪个窗口，作为一句话发给大模型；气泡里会写明要发几行。

### 桌面上的她：不挡事、省电、提醒

- **全屏时躲开**：判断别人在全屏、在演示用 Windows 给通知用的接口 `SHQueryUserNotificationState`（系统弹通知前也问它），全屏游戏、视频、F11 浏览器、幻灯片放映、锁屏都认得。Electron 没有这个接口，又不想加原生依赖：主进程开一个常驻的 PowerShell，每 1.5 秒问一次、变了才打印；它自己盯着艾拉的进程号，艾拉没了它就退出（`main/presence.ts`）
- **免打扰**：开会共享屏幕判断不了（不一定全屏），所以有手动的免打扰：藏起来、唤醒词不应声（`VoiceController.muted`）、看到报错先记着、任务进展不说、提醒改成系统通知。明确叫她（对话框、「听我说」）时自动退出
- **省电**：透明置顶窗口全天满帧很费电。没人理她（只在呼吸眨眼）时每秒 20 帧，鼠标在动（视线在跟着转）时 30 帧，说话、被点、对话框开着时不限；拔电再降到 12 / 24 帧。跳过的帧时间照样算进动作，速度不变（`scene/frameBudget.ts`，有测试）。藏起来时 Chromium 本来就不画
- **提醒**：AI 服务把时间算好推一个 `reminder` 事件，主进程存在 `userData/reminders.json`（AI 服务不存用户数据）。到点：她在桌面上而且能说话 → 她说；藏起来了 → 系统通知（开会时也不会漏）。电脑睡眠醒来、解锁时马上补看一遍；闹钟最长隔一小时重排一次。规则在 `main/reminders.ts`（纯逻辑，有测试）
- **久坐提醒**：每分钟看一次系统空闲时间，空闲 5 分钟以上就当休息过了、重新计时；全屏、演示、免打扰时不提醒
- **开机启动**：只在打包装好的版本里能设（开发时注册的是裸的 electron.exe）
- 偏好存在 `userData/settings.json` 的 `desktop` 字段；状态变了整份推给所有窗口（`desktop:status`）。改偏好、免打扰、删提醒只认主窗口，「10 分钟后再提醒」只认角色窗口

### 她知道你在忙什么、拖文件、剪贴板、动作

- **每天见面和日报**（`main/briefing.ts`，纯逻辑有测试）：材料都在本机——编程任务的会话（`/agent/sessions`）、记忆里今天到期的日程、提醒、今天的聊天记录。话由代码拼出来，不调大模型：快、不花钱、数字都是真的。凌晨 5 点前还算前一天；程序刚启动时她已经打过招呼，就不再说「早上好」，没什么可说就不说。今天说过没有存在 `userData/settings.json` 的 `briefing` 字段。每分钟看一次，要满足：她在桌面上能说话、人在电脑前（系统空闲不到 2 分钟）、AI 服务开着
- **拖文件**（`shared/drop.ts`、`main/drops.ts`）：渲染层拿不到路径以外的东西——路径由 Electron 从拖进来的文件取，主进程看一眼（大小、是不是文本、是不是密钥文件、在哪个 git 仓库），只把「刚拖进来的文本文件」放进 10 分钟的白名单，角色窗口只能读白名单里的。拖文件时系统不发鼠标移动，所以「光标在不在她身上」也用主进程推的光标位置判断，窗口才接得住
- **剪贴板**：只有你提到剪贴板（打字、说话、右键菜单）才读，内容打码后和你的话一起发
- **动作**：`PoseState` 多了手臂（`armRaise`、`forearmSwing`、`armsUp`、`typing`），`VrmAvatar.armAngles` 按权重叠：放下 → 敲键盘 → 挥手 → 伸懒腰；角度是按 VRoid 示例模型调的，换原创形象后可能要微调

### 她的作品和她的一天

- **作品**（`shared/studio.ts` 的规则、`main/studio.ts`、`shell/StudioPage.vue`；AI 服务那边见 aila-ai 的「她的作品和日记」）：设置 → 桌面里「自己做点东西」选个周期（默认不让她做：会花钱），主进程的管家每个周期里随机挑个时刻（周期的 60%～140%），到点了、你又有一阵子没碰键盘鼠标，就把她记得的你的事、最近的任务、今天是什么日子交给 AI 服务，她挑个点子开始做；一直等不到你空下来，过了 6 小时也照做。做的时候桌面上的她「敲键盘」；做好了、你在电脑前时冒气泡「要看看吗」，点「看看」打开作品页。网页作品在单独的沙盒窗口里打开：没有预加载、单独的会话分区里只放行这件作品自己的文件，AI 服务给的时候还带了最严的 CSP（不能联网、碰不到本机的接口）。她做作品的会话在任务列表里也看得到（要你点头的操作照样在「等你」里），但不算进每天见面、日报、日记里「你的任务」。
- **她的一天**：第一次见面的日子记在 settings.json 的 `life` 里，认识第 100、200 天、周年和几个公历节日早上提一句，那天也会做一件和它有关的作品；早上说说昨天她做的作品；记忆里的日程提前一天说「明天……准备得怎么样」，过了一两天问「后来怎么样了」；深夜（23:30～4 点）你还在用电脑，说一次早点睡。
- **日记**：晚上十点以后管家把今天真的发生的事（任务、聊了几句、认识第几天、今天的日子）交给 AI 服务，她写一篇（没有大模型时按材料拼一段），一天一篇、写过不改。设置 → 桌面里能关。
- **小情绪**：她在任务里跑测试（`isTestCommand` 认 pytest、vitest、npm test、mvnw test……），主进程按退出码数连着没过几次：之前没过、这次过了，她高兴地说一句；连着三次没过，叹口气、打打气。
- **性格**：设置 → 形象里的「性格」：说话风格（温柔、元气、冷静、爱吐槽）、怎么叫你、口头禅，存在 AI 服务的设置里，对话、日记、挑作品点子都按这个来。

### 记忆和设置

- **记忆在主进程**：和聊天记录一样存在本地（`memories.json`）、经云端同步；每次对话主进程把记忆附在请求里交给 AI 服务挑相关的。她说完一轮后，记忆管家等 1.5 秒（你可能马上接着说），把最近三轮对话交给 AI 服务整理，按返回的操作更新记忆；同一轮不重复整理，AI 服务没开时这轮就不记，不打扰你。
- **删除优先**：云端说删了，本地哪怕有没传上去的修改也一起删；上传修改时云端返回 410（已经删了），就放弃本地的修改。用户在一台电脑上让她忘掉的事，不会被另一台电脑复活。
- **设置窗口是第二个窗口**：加载同一个页面，按地址决定显示角色还是设置；两边的全局样式不一样（角色窗口全透明），所以入口按需加载。状态变化（同步、记忆、语音开关）由主进程广播给两个窗口；语音开关存在角色窗口里，设置窗口经主进程读写。
- **设置窗口碰不到密钥原文**：读设置时 AI 服务只返回「设没设」；「在文件夹里显示」只认几个固定的名字（配置、模型、数据），路径由主进程问 AI 服务，渲染层不能指定任意路径，打开时也只在资源管理器里定位，不会执行文件。

### 语音

- **气泡和语音用摘要**：对话只念服务标出来的摘要，正常说完的回复在「对话」页保留全文。气泡里的「看全文」会在原处展开可滚动的全文，关了出声也一样。没标摘要时由服务挑开头适合念的一两句，必要时她会加一句「细节在对话框里」，这句提示不进历史。连接旧版服务时照常全文朗读。
- **按句合成，第一句切短**：回复边收边切句，第一句遇到逗号就切（至少 4 个字），合成好立刻播放；播当前句时后一句已经在合成。所以开口时间只取决于第一句，后面不会停顿等待。
- **文字跟着声音走**：一句的字按这句声音的长度逐字显示（比声音稍快一点），表情、动作标签在说到那里时触发；合成失败的句子退回打字节奏，不会卡住。
- **口型由声音驱动**：播放时用 AnalyserNode 取音量和频谱，音量决定张多大，中频强偏「啊」、高频强偏「衣」「诶」、低频强偏「乌」「哦」，驱动 VRM 的五个元音口型。没出声时还是原来的假口型。
- **回声分两层挡**：麦克风开着浏览器自带的回声消除，她自己的声音基本进不来；万一漏进来，识别结果和她最近说的两句比较，六成以上的字对得上就当回声忽略。只在她说话时和刚说完 1.2 秒内检查，免得把你说的「好的」当成回声。
- **插话先压低音量再停**：她说话时听到你开口，先把音量压到 25%，等识别结果出来确认是在说话才打断；咳嗽、语气词之类的会恢复音量接着说。服务还没发完时只记已显示的片段，全文已经收齐时保留全文。
- **会话状态在桌面端**：AI 服务只管「听」（等唤醒词 / 断句识别），什么时候回到等唤醒词由桌面端决定，因为只有它知道她是不是还在说话、你是不是还在追问。
- **延迟统计**：每次记录「说完到开口」并拆成断句等待、识别、大模型和首句合成三段，控制台打印；`__aila.voice.latencySummary()` 给出 P50 / P95。
- **不开麦克风也能调试**：开发模式下控制台执行 `__aila.hear('你好艾拉，明天天气怎么样')`，用她自己的合成声音模拟你说话，整条链路（唤醒 → 断句 → 识别 → 对话 → 合成 → 播放 → 口型）照常走一遍。
