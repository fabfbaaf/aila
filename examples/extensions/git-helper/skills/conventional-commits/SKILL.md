# 约定式提交

先看项目最近的提交（`git log --oneline -20`）：项目已经有自己的写法（比如中文一句话），就照项目的来，这项本事不用。

格式：

```
<类型>(<范围，可选>): <一句话说明>

<正文，可选：为什么改、和原来有什么不同>

<脚注，可选：BREAKING CHANGE: ……、Closes #123>
```

类型只用这几个：

| 类型 | 什么时候用 |
|---|---|
| feat | 加了用户能感觉到的新功能 |
| fix | 修 bug |
| docs | 只改文档 |
| refactor | 不改行为的重构 |
| test | 只加、改测试 |
| perf | 性能 |
| build / ci | 构建、依赖、CI 配置 |
| chore | 其他杂事 |

要点：

- 说明用祈使句、不加句号，72 个字符以内
- 一个提交只做一件事；改动里混了两件事，先问用户要不要拆开
- 不兼容的改动在类型后面加 `!`（`feat!: ……`），脚注写 `BREAKING CHANGE:` 说明怎么迁移

例子见同一个文件夹里的 `examples.md`（用 read_skill 的 file 参数读）。
