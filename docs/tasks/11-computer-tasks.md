# 11 电脑任务：用命令行帮你操作这台电脑

**先决条件：Claude 的「长任务和整体规划」合并以后再开。** 两边都要改 `runtime/runner.py`、`permissions.py`、任务页，同时做冲突太多。开始前先读那次合并的结果说明，电脑任务要能用上长任务。

## 背景

编程任务里她本来就能跑命令（Git Bash / PowerShell），所以开程序、用 PowerShell 操作 Office（COM）、整理文件、管进程、用 winget / ffmpeg / git 这些命令行工具，技术上都做得到。缺的是：

- 任务一定挂在一个项目文件夹上，命令也在那里跑；「帮我把下载文件夹按类型整理一下」这种事没地方开
- 她不知道这台电脑装了什么，只能瞎猜
- 权限是按项目文件夹设计的（「工作区内自动」），对整台电脑不合适

**不做界面自动化**（点窗口里的按钮）：只用命令行和脚本接口。没有命令行的程序（比如微信）做不了，结果说明里写清楚。

下面每条规则都是和桔梗讨论定下来的，照做；拿不准的写进结果说明，不要自己放松。

## 要做的

1. 新的会话类型「电脑任务」
   - `Runtime.create` 支持不选项目：会话的 `start` 事件里 `kind: "computer"`，工作目录是用户目录（`Path.home()`）；`Session.summary()` 带上 `kind`
   - 不能「在新分支上做」；花费上限、撤销一轮、压缩、长任务都照常能用
   - 会话开头的环境说明换一份（见第 4 条），系统提示词**不换**（前缀缓存）：电脑任务的做事规矩放在环境说明里
2. 权限（`permissions.py`，写进模块开头的说明）
   - 电脑任务只有两种模式：只读、先问再改。**没有「工作区内自动」**（接口、终端、桌面都不给选，传了就拒绝）
   - 读文件、列目录、搜索：不用问
   - 改文件、写文件：每次都问（可以选「这个会话里改文件都不用问」，和编程任务一样）
   - 命令：明显只读的直接跑；其他每条都问，可以选「这条命令以后都不用问」——记在单独的「电脑」范围里，不和任何项目混
   - 危险命令（删除、改系统设置、关机重启、装卸软件、改注册表、结束别人的进程……）任何模式都要问，也不能「以后都不用问」；`permissions.py` 的危险命令列表按需要补（`shutdown`、`Restart-Computer`、`winget install/uninstall`、`reg add/delete`、`Set-ItemProperty HKLM:`……）
   - **受保护的位置**：`AppData`、`.ssh`、`.gnupg`、浏览器的配置和登录数据（Edge、Chrome、Firefox 的用户目录）、密码管理器的数据、艾拉自己的 `aila-ai/.env` 和数据目录——读、改、命令里带到这些路径都要问，而且**不能「以后都不用问」**
   - 问的时候给你看的内容由代码生成（命令原文、diff），不用模型的描述
3. 入口
   - 桌面任务页：「新任务」里加一项「不选项目，操作电脑」；会话列表、顶栏显示「电脑」而不是项目名；新任务的权限模式只给两种
   - 对话：她判断你要她在电脑上**动手做好几步**的事时，先问一句「开个电脑任务做？」（对话现有的确认气泡），你同意后开电脑任务（照 `app/tools/coding.py` 交编程任务的写法），桌面端打开任务页接上
   - **一两步的小事在对话里直接做**：对话新加一个技能包「电脑操作」，只有一个工具：跑一条 PowerShell 命令。只读命令直接跑；其他的走对话现有的确认（`APPROVED`），给你看的是命令原文；危险命令和碰到受保护位置的照样问、不能记住；默认关闭，在设置里打开
   - 终端：`aila --computer` 开电脑任务（从用户目录开始）
   - 接口：`POST /agent/sessions` 多一个 `kind: "computer"`（不用给 `cwd`）
4. 告诉她这台电脑有什么
   - 电脑任务的环境说明里写：系统版本、用户目录、常用目录（桌面、文档、下载）、**装了哪些程序**（开始菜单里程序的名字）、**命令行里有哪些工具**（`git`、`node`、`python`、`code`、`ffmpeg`、`docker`、`winget`、Office 有没有装……按 `PATH` 里找得到的列，只写名字）；**不写文件内容、不写文件列表**
   - 再附一份不长的「Windows 上常用操作的写法」（开程序和文件、PowerShell 操作 Excel / Word、剪贴板、通知、计划任务、按类型整理文件、批量改名），控制在 1500 字以内
   - 批量操作的规矩写进去：**先列出要动哪些文件、怎么动，等用户看过再做**；移动、改名这类命令做的事「撤销这一轮」退不回去，要说在前面
   - 设置页 → 编程里加一个开关「告诉她这台电脑装了什么」（默认开），旁边能点开看这段具体写了什么；关了以后只写系统版本和常用目录
   - 这段在会话开始时生成，写进 `start` 事件后不再改（前缀缓存）；探测要快（几秒内），失败就少写，不要卡住开会话
5. 文档：`aila-ai/README.md`、`aila-desktop/README.md`；`docs/real-test-plan.md` 加一节「电脑任务」：整理一个测试文件夹、用 PowerShell 读一个 Excel、在对话里让她「打开记事本」、试一条危险命令看是不是问、试读 `AppData` 下的文件看是不是问

## 不要改

- 编程任务（有项目的会话）的权限规则和行为
- 系统提示词（`runtime/prompt.py` 的 `SYSTEM_PROMPT`）
- 对话里已有技能包的行为

## 验收

- `aila-ai` 新测试（`tests/test_computer_tasks.py`，`Scripted` 模型）：
  - 电脑任务开在用户目录（测试里用临时目录代替 `Path.home()`）、不能选「工作区内自动」、不能在新分支上做
  - 权限：读不问；改文件问；只读命令不问、其他命令问、记住以后不问；危险命令和受保护位置每次都问、不能记住；只读模式下改和跑非只读命令被拒
  - 环境说明：有程序名和命令行工具名，没有文件内容；关掉开关后没有程序列表；探测失败不影响开会话
  - 对话的「电脑操作」：只读命令直接跑，其他要确认，危险命令不能跳过确认
  - 接口、终端 `--computer` 能开电脑任务
- 桌面：新任务能选「不选项目」；电脑任务只给两种模式；会话列表显示「电脑」
- `AGENTS.md` 里的测试全过
- 结果说明 `docs/tasks/11-computer-tasks-result.md`，写清楚做不到的（没有命令行的程序）
