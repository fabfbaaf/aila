# 艾拉 · 真实测试计划

第 1–6 周的功能都做完了，自动化测试也都过了（AI 服务 214 个、桌面端 86 个、云端 26 个），但都是用假模型、假网站、程序画的截图测的。这份计划用**真大模型、真麦克风、真网站、真的写代码过程**把每块走一遍：找出问题，顺便攒下简历上能写的数字。

**分工**：密钥、账号、麦克风、登录网站由你来做；遇到问题你在对话里说一声，我看终端日志（aila-ai / aila-server / aila-desktop 三个标签页）定位、修复、补测试。每做完一块打个勾，问题记到最后的表里。

**建议顺序**：0 → 1 → 2 → 6 → 7 → 8 → 3 → 4 → 5 → 9 → 10。先把真模型接通（后面都依赖它），语音最依赖环境，放在中间。每块 10–20 分钟，全部做完大约半天。

## 12. 编程 Agent：终端版 aila（需要大模型密钥）

先把 `aila-ai` 目录加进 PATH，在一个自己的项目里（有测试的最好，先 `git commit` 一下，改坏了能回去）打开终端。

| # | 做什么 | 期望 / 记录 |
|---|---|---|
| 12.1 | `aila`，问「这个项目是做什么的，怎么跑测试」 | 先找文件、读 README 和配置，答得具体（命令、目录）；不改任何文件 |
| 12.2 | `/init` | 写出一份 AGENTS.md（写之前问你，给你看内容）；下次开会话时开头带上它 |
| 12.3 | 让她加一个小功能并写测试（比如「给购物车加一个打折函数，写单元测试并跑通」） | 列待办清单 → 读相关代码 → 改文件前问你（给 diff）→ 跑测试前问你 → 测试没过会看输出再改。记录：成功没有、几步、用时、每轮结束那行的缓存命中率 |
| 12.4 | 改文件时选 `2`（以后都可以） | 这个会话后面改文件不再问；跑测试的命令选 `2` 后同一条命令不再问 |
| 12.5 | 她做到一半按 `Esc` | 立刻停下（正在跑的命令也停）；说「继续」接着做 |
| 12.6 | 让她「把 build 目录删掉」或者「push 到远程」 | 就算在 `--mode auto` 也要问，而且没有「以后都可以」 |
| 12.7 | 她要读 `.env` 时 | 先问你（内容会发给大模型） |
| 12.8 | 关掉终端，再 `aila -c` | 之前的过程重放出来，接着说能接着做 |
| 12.9 | 桌面端和 AI 服务都开着时用 `aila` | 头部写「本地服务」；同一个会话以后在桌面工作窗口里也能看到（第 3 周做） |
| 12.10 | 一个长任务做完后 `/usage` | 记下总输入、命中缓存的比例（简历数字：缓存命中率） |
| 12.11 | `aila -p "这个项目有多少个测试文件" --mode read_only` | 只打印答案，退出码 0；放进脚本里能用 |
